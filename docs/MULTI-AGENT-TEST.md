# Reproducible Claude Code ↔ Codex collaboration test

**Status as delivered:** Not yet executed with the two actual coding-agent CLIs. The application and API tests are real and have been run; Concord's cross-client behavior remains to be verified on a machine with both clients.

## Goals

1. Two separate clients discover one shared Concord workspace.
2. Both attempt to claim `public/app.js`; Concord reports overlap before a conflicting edit.
3. Codex claims backend-only files instead; Claude keeps frontend ownership.
4. Both clients exchange contract decisions using `update_work` (live prompt if adapters support it, otherwise durable state).
5. Each agent hands off evidence (`finish_work`) including file changes and test results.

## Preparation

1. Run `npm test` and `npm start` to establish the baseline.
2. Review `CONFIG-AUDIT.md`, then execute the isolated PowerShell setup script.
3. Check `concord status`, `concord doctor`, and `concord adapters status`; record versions and delivery mode.
4. In terminal A, open Claude Code from the repository root.
5. In terminal B, open Codex using `scripts/run-codex-sandbox.ps1`, also pointing to the same root.

For Claude Code, the `.mcp.json` generated by the script is project-scoped. If your client does not load it, inspect its MCP configuration before proceeding.

## First prompt — Claude Code

> We are demonstrating Concord MCP coordination. Use Concord's `start_work` before touching any files. Claim task "Frontend priority filter" and scope `public/app.js` plus `public/styles.css`. Read the task board, add an accessible priority filter (All / High / Medium / Low) without changing the API. Record your implementation choice via `update_work`. Respect overlaps and do not edit files owned by another agent. Run `npm run check` and `npm test` and finish with a review-ready handoff with evidence.

## Second prompt — Codex (run after Claude claims its scope)

> We are demonstrating Concord MCP coordination with Claude Code. Before editing, use `start_work` to attempt to claim `public/app.js` for task "Sprint summary API" and report Concord's overlap signal. **Do not edit a conflicting file.** Change the proposed scope to `server/api.js` and `test/api.test.js` and claim this backend task. Implement GET `/api/summary` returning `{total, backlog, progress, done}` and integration tests. Communicate the response schema through Concord `update_work`, run `npm run check` and `npm test`, and use `finish_work` to mark the task review-ready with exact test evidence.

## Pass criteria

- Both agents are identifiable as distinct clients working in the *same* workspace.
- Overlap is detected before an edit, and the conflicting claim is resolved.
- No backend/frontend collisions in the final diff.
- API contract and one design decision are visible in shared Concord state.
- Both agents produce verifiable evidence; all tests pass.

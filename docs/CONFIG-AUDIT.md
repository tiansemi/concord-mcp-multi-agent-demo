# Concord MCP configuration audit (read BEFORE installing)

Checked against the upstream `Get-Concord-AI/concord-mcp` README and `docs/claude-code.md` / `docs/codex.md` on **6 November 2026**. Concord is evolving quickly; inspect the installed version's help before trusting automated changes.

## What a standard `concord setup` can change

| Location | Expected effect | Scope |
| --- | --- | --- |
| `.concord/` | Local SQLite workspace, task records, handoff/review outputs, ignore rules | This repository |
| `.mcp.json` | Register MCP server for Claude Code | This repository |
| `CLAUDE.md`, `AGENTS.md`, `.codex/` | Agent instructions, collaboration rules | This repository |
| `.cursor/mcp.json`, `.cursor/rules/`, `.gemini/settings.json`, `.grok/config.toml` | Register Concord/instructions for other supported agents | This repository |
| `~/.codex/config.toml` or `$CODEX_HOME/config.toml` | Register Codex MCP server | **Normally user-global** |
| `~/.concord/config.json`, user-level agent files | Optional global integration after interactive consent | **User-global** |
| Global Concord adapters/plugins | Hook/monitor/app-server integration for live messaging | **User-global** |
| Concord Cloud | Optional cloud link, separate from local setup | Cross-machine if opted in |

Do not run the default setup against a professional repository or machine-wide agent config merely to try the tool. The default setup can affect user-global configurations. Concord telemetry can be disabled with `CONCORD_TELEMETRY_DISABLED=1`.

## Isolation strategy used by this demo

`scripts/setup-concord-sandbox.ps1` deliberately:

1. Installs the npm package only into `.sandbox-tools/` (no `npm install -g`) and temporarily points `HOME`/`USERPROFILE` to `.sandbox-home/` during setup, avoiding changes to the normal `~/.concord/` preferences.
2. Sets `CODEX_HOME` to `.sandbox-codex/`, so the Codex MCP registration is not written into the existing real Codex profile.
3. Runs `concord setup --no-global --no-adapters --no-mcp`: local workspace and agent instructions only.
4. Writes a project-level `.mcp.json` with an absolute path to the sandbox MCP shim.
5. Writes a project-local Codex `config.toml` with the same MCP shim, setting `CONCORD_REPO_ROOT` and `CONCORD_ALLOWED_ROOTS`.
6. Disables optional product telemetry and update checks for the test process.
   Hardening: the package is installed at an exact version (default `0.20.0`, the latest release on 6 November 2026; override with `-ConcordVersion`) with `--ignore-scripts` and a project-local npm cache/userconfig. `HOME`/`USERPROFILE` stay redirected for the whole run (including `status`) and are also set in the registered MCP servers' `env`. Existing `CLAUDE.md` / `AGENTS.md` are backed up to `*.bak-<timestamp>` first.
7. Leaves any existing `.mcp.json` or sandbox `config.toml` untouched and stops instead of overwriting them.

The `.sandbox-home/` directory and generated `.mcp.json` are machine-local and intentionally excluded from the published Git repository (see `.gitignore`). `CLAUDE.md` / `AGENTS.md` generated by setup may be reviewed and committed deliberately if desired. Add them only after checking their content.

**Important limitation:** `--no-adapters` keeps global hook/monitor integrations out of scope. The clients may still share task state via MCP, but immediate prompts to an idle agent can be unavailable. `concord adapters status` and `concord doctor` determine actual capability. If the demo requires live wakeups, inspect `concord adapters install --help` and opt into global adapter installation separately; do not claim live delivery until verified.

## Requirements

- Windows 11 PowerShell (script targets Windows); Node.js **20+** and npm.
- Claude Code CLI and Codex CLI installed separately, with valid user access. These tools are **not** bundled.
- No credentials, tokens, or work repositories copied into this project.
- Local API bound to `127.0.0.1` by default.
